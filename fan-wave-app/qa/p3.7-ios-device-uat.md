# P3.7 — iOS parity / physical-iPhone UAT (final device checklist)

**Status: CODE/AUTOMATION READY — iOS DEVICE VERIFICATION REQUIRED.**
No iOS build has been cut in the v9.5 stability program and nothing in it
has run on an iPhone. The iOS Jest preset (the default `jest-expo` preset,
`npm test`) is green; that is not device verification.

Purpose: confirm the complete v9.5 stability work behaves correctly on iOS
and that Android-motivated fixes did not regress iOS.

Build under test: an EAS `preview` iOS build (internal distribution) at
v9.5.34 or later, installed on a physical iPhone (a notched or Dynamic
Island model preferred). Sandbox Apple ID for purchases: NOT
fansphere.reviewer@gmail.com (its entitlement bypass fakes Premium).

Known-by-construction differences to keep in mind while testing (from the
parity review; not defects):

- The video memory cap (`maxBufferBytes`) is Android-only; on iOS only the
  5 s forward buffer applies. Record iOS memory as its own baseline.
- `videoQuality` 720p is an iOS-only knob and is now set on all five
  capture paths (Clips FAB, Clips library, New Clip, chat camera, Moments).
- iOS emits `inactive` on the notification shade, app switcher and calls,
  which cancels the 0–2 s resume-refresh timer each time.
- iOS purges the Caches directory under disk pressure, so the
  `file_missing` upload branch will be seen more often than on Android.

## Platform.OS branch parity (from the P3.7 audit at HEAD)

`Platform.OS` is the only platform-branch mechanism in the codebase: 54 sites
in 28 files, no `Platform.select`, no `.ios.tsx`/`.android.tsx` modules. The
audit classified every site; the intended ones are genuine API differences
(RevenueCat store keys and "App Store" copy, subscription-management links,
Android notification channels vs iOS `app-settings:`, keyboard `padding` vs
`height`, iOS inline datetime picker vs Android dialogs, Share `url` vs
message, TikTok scheme probing, web-vs-native storage). Accidental gaps found
and their disposition:

| Gap | Disposition |
| --- | --- |
| Microphone and photo-add usage strings not explicit in app.json | Not a crash: `expo-image-picker` and `expo-media-library` are in Expo's auto-applied plugin list, so default strings were injected. Explicit purpose strings added in v9.5.35 (row 13 verifies the prompts read correctly) |
| ClipCommentsSheet, ClipShareSheet, WCTeamFollowModal had no bottom safe-area inset (magic 34 pt in one) | Fixed in v9.5.35 with `useSafeAreaInsets`; rows 11, 23 and the Soccer Cup follow sheet verify placement |
| Video memory cap is Android-only | By construction; row 30 records the iOS baseline |
| eas.json `preview` has no `ios` block | Owner decision: add an internal-distribution iOS block with registered UDIDs, or use TestFlight from `production`. Needed before this checklist can run |
| Sentry Expo plugin absent (no dSYM upload) | Owner action: plugin + `SENTRY_AUTH_TOKEN`; row 31 still works, but crashes arrive unsymbolicated |
| `allowsEditing` removed from avatar pick for both platforms because of Android's cropper | Product decision; not changed. Row 1 sign-up can include an avatar pick to confirm the un-cropped result is acceptable |
| "Copy Link" produces `/clip/<id>` which has no route or web page | Same on both platforms; product backlog |
| CI ran only the iOS jest preset | Fixed in v9.5.35: CI now runs both presets |
