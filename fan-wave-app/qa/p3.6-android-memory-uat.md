## Review-derived focus items (from the P3.6 code review of ae9cded..HEAD)

Headline of the review: no Phase 2/3 change touched the two mechanisms behind
the S10+ OOM (buffer option values are byte-identical; one player, one
VideoView). It found one new unbounded resource and two pre-existing players
without buffer caps; all three are fixed in v9.5.35 and must be verified on
the device below.

| # | Item (fixed in v9.5.35) | Reproduce | Watch |
| --- | --- | --- | --- |
| R1 | expo-video disk cache: P2.10 enabled `useCaching` with the 1 GB default; now capped at 256 MB at boot | Scroll 8–10 pages of Clips (~150 clips) tapping play on every third card for 30 min; before starting run `adb shell run-as org.fansphere.app du -sh cache` and repeat every 5 min | Java Heap and Graphics flat; `cache` size plateaus at or under ~256 MB; no `SimpleCache`/`CacheDataSink` warnings in logcat |
| R2 | Moments feed per-card players had no buffer options (ExoPlayer 50 s default, 3–5 alive at once); now `CLIP_FEED_BUFFER_OPTIONS` | Open a fan group with 10+ video moments; scroll the Moments feed up and down for 5 min | Java Heap staircase toward 256 MB Dalvik limit must NOT appear; `logcat | grep -i "GC_FOR_ALLOC\|OutOfMemory"` empty |
| R3 | Chat fullscreen preview player had no buffer options; now `CLIP_PREVIEW_BUFFER_OPTIONS` | Open 5 chat videos fullscreen in a row | Java Heap returns to baseline after each close |
| R4 | Stall timer from the previous source could fail a healthy card (B→A with A loaded); cleared in effect cleanup | Scroll A→B→A quickly, wait 15 s on A | No "Couldn't load this video" on a playing card |
| R5 | Poster cache and auth-telemetry maps were never pruned; now bounded | 30 min of pull-to-refresh and filter switching (For You / Following / Trending) | Java Heap flat |
| R6 | Realtime onReconnect spread timers were untracked (held the entry up to 3 s past teardown); now cleared with the entry | With Clips and a chat open, toggle airplane mode every 20 s for 10 min | Java Heap and `Views`/`Activities` counts flat; `getRealtimeDiagnostics()` channel count does not drift |
| R7 | Every posted clip left its 25 MB picker copy on disk; now deleted after the row insert | Post 3 clips, then `run-as … du -sh cache` | Cache does not grow by 3 clips |
| R8 | Kill-switch hook re-subscribed on every render (churn); analytics AppState listener now removable; offline probe timer cleared on failure | No separate step; covered by the extended runtime | — |

Not changed (pre-existing, noted for the soak): the game chat message list has
no cap or FlatList windowing (text rows, KB-scale); `hydrationKey` is now
memoised but still recomputed per clips change.
