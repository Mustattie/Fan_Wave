# v9.5.11–v9.5.14 UAT — Email Confirmation + App Links

Covers the four commits merged in PR #20. Everything server-side and
site-side is already verified (see "Already proven" at the bottom) — this
checklist is only the parts that need a real device.

**Builds under test**

| Platform | Profile | Version | Why this artifact |
|---|---|---|---|
| Android | `preview` (APK) | versionCode 25 | EAS-signed with `84:DE:16:E9:…`, which **is** in `assetlinks.json` |
| iOS | `production` | build 36 | TestFlight; associated domains work there |

> **Do not UAT App Links on a bundletool-converted APK.** That path signs with
> the local **debug** keystore (`f0a4d5e0…`), which is deliberately *not* in
> `assetlinks.json` — the Android debug key is effectively public, and listing
> it would let any debug-signed app claim fansphere.org links. A bundletool APK
> will report `unverified` and look like a failure that isn't one.

---

## 1. Android App Links (the core fix)

Install the preview APK, then:

```sh
adb shell pm get-app-links org.fansphere.app
```

- [ ] Output shows `fansphere.org: verified`

If it says `unverified`, force a re-check before concluding anything — a device
can cache a failed lookup from before the site went live:

```sh
adb shell pm verify-app-links --re-verify org.fansphere.app
```

Then, with the app **installed**:

- [ ] `adb shell am start -a android.intent.action.VIEW -d "https://fansphere.org/party/<real-uuid>"` opens the app on the watch-party screen — no browser, no chooser
- [ ] Same for `https://fansphere.org/group/<real-uuid>` → fan-group screen
- [ ] Tapping a real SMS/WhatsApp party invite opens the app directly

## 2. iOS Universal Links

- [ ] Safari → `https://fansphere.org/party/<real-uuid>` → opens the app on the watch-party screen
- [ ] Same for `/group/<real-uuid>`
- [ ] Tapping a real invite from Messages does the same

Apple caches the association file for an hour and devices cache longer. If it
opens Safari instead, reinstall the app before treating it as a failure.

## 3. Email confirmation — the v9.5.11 fix

**Desktop half** (this is what the tester originally reported as broken):

- [ ] Sign up with a new address, open the confirmation link **on a computer**
- [ ] Page says "Email confirmed" — **not** a blank page, not a 404
- [ ] It explains the last step happens on the phone
- [ ] Signing in on the phone with that account works

**Phone half:**

- [ ] Open the same style of link **on the phone** → app opens and lands signed in (not `+not-found`)
- [ ] Password reset link → app opens on the reset-password screen

**Expired link:**

- [ ] Use a confirmation link twice → second time says the link expired and points at Resend — it must **not** claim success

## 4. REGRESSION — `/auth/` must NOT be captured by the app

This is the highest-value check here. `/auth/` is excluded in the AASA
specifically because the page has to run in a *browser* to forward its tokens.
If App Links swallow it, email confirmation breaks in exactly the way v9.5.11
fixed.

- [ ] On a phone **with the app installed**, tapping a confirmation email link opens a **browser** showing the confirmed page — it must not jump straight into the app at a "not found" screen
- [ ] `adb shell am start -a android.intent.action.VIEW -d "https://fansphere.org/auth/"` opens a browser, **not** the app

## 5. Shared-link web fallback (v9.5.13)

On a device with the app **uninstalled**, or any desktop browser:

- [ ] `https://fansphere.org/party/<uuid>` → "You're invited to a watch party" + store badges
- [ ] `/group/<uuid>` → fan-group copy
- [ ] `/clip/<uuid>` → "A clip was shared with you" — **no** "Open in Fan Sphere" button (there is no clip screen yet; the button would dead-end)
- [ ] `/moment/<uuid>` → moment copy, also no open-in-app button
- [ ] None of them land on the marketing homepage

## 6. Sanity regressions around the auth changes

- [ ] Fresh install → sign up → onboarding runs (sports, teams, location)
- [ ] Sign in as an onboarded account → sign out → sign up a **new** account in the same session → the new account gets onboarding, not the previous account's Home (the v9.5.10 fix)
- [ ] Sign out clears state; signing back in restores teams

## Already proven — do not re-test by hand

Verified against live production on 2026-09-16:

- `assetlinks.json` → `200`, `application/json`
- Google Digital Asset Links API → both fingerprints, **no `errorCode`**
- Apple CDN (`app-site-association.cdn-apple.com/a/v1/fansphere.org`) → `200`, body byte-identical to the repo file
- `/auth/`, `/open/`, `/invite/` → `200`
- `/party/<uuid>` → serves `404.html` carrying the `/open/` routing table
- `tsc` clean, 49 unit tests, 15 jsdom checks on the auth bridge, 23 on the landing page + routing table

A CDN hit proves Apple *has* the file. Only sections 1–2 above prove the chain
end to end.
