## Nullable kickoff (as asked)

`gameTimeForWrite` (`_shared/gameTime.ts:10-13`) is right, and `gameChanged` does treat string→null as a change, so the sync **will** write null over a stored fake time — but only when ESPN sends `timeValid === false`. If the provider merely omits the date, the stored fake time is preserved by design, so the World Series rows the 10-15 note asked about are only cleared if ESPN marks them explicitly TBD. Three downstream effects:

1. **Realtime goes stale.** `mapGameRealtimePatch` only patches time when `row.scheduled_at` is truthy (`mappers.ts:270`). A live TBD transition leaves the card showing the old kickoff until a full refetch. Two-line fix; low severity but directly in this change's blast radius.
2. **Ops alert blind spot.** `ops_health_problems()` counts `scheduled_at BETWEEN now() AND +3 days` (`092:82`) and alarms under 5. TBD rows are invisible to it, so it cannot distinguish "sync broken" from "sync wrote TBDs."
3. **WCSchedule is not null-safe.** It normalizes stage/metadata/venue/status at the load boundary but not `scheduled_at` (`WCSchedule.tsx:173-179`), while `WCGameRow` declares it non-null. A null would group under a 1970 date header and sort first. WC cron is disabled (066), so this is latent, not live — but it reopens if WC sync is re-enabled.

Home-feed exclusion of TBD rows (`homeGameQuery.ts:15-16`) and non-expiry by the timestamp crons (041/042) are both already stated as accepted limits.
